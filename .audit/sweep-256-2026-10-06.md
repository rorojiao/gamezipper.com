## Known limitation documented (color-switch Kachilu headless rAF suppression)
The color-switch game loop depends on `requestAnimationFrame` to render the canvas. Kachilu's headless CDP backend keeps the page in `document.visibilityState === "hidden"` state, which Chromium throttles rAF to 0 fps in hidden tabs. This is **not a production bug** — the IIFE-scoped game loop is correctly registered (index.html L1070 `requestAnimationFrame(loop)` + L1138 boot), and the production engine passes 30/30 levels when frames are manually driven via the verifier harness. The R157/R342 R336 IIFE template is for live-browser probes (Kachilu eval after Play click) and doesn't manually drive rAF — the verifier harness does. This affects all rAF-driven arcade games probed in Kachilu headless (color-switch, slope, drive-mad, etc.). For these games, the per-game verifier is the authoritative PASS/FAIL signal; live-browser Kachilu only verifies the menu/level-select/initial-state rendering.
