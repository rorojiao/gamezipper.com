## BI 7d dead_click root-cause analysis
gz-analytics.js line 401 dead_click detector (capture-phase on DIV/SPAN with `lookClickable` className regex `/click|card|btn|tile|thumb|seg/i`):
1. Snapshot target's className
2. setTimeout 1500ms → if className/aria-expanded/inline-style unchanged → fire `ps('dead_click', {u:P, sel})`

For the 3 R876 games, the **captured target** is the child (`.lvl-tile` / `.level-tile` / `.card-name`) but the **state change** happens on the parent or via a screen flip (the tile's own className never changes). The detector correctly sees no className delta on the captured child → fires dead_click. The clicks were successful — players DID enter the level — but the BI signal was a false positive caused by the detector's className-on-captured-target heuristic.

Fix (mirrors R875 hud-btn/key pressed pattern, validated 2026-10-08):
- color-switch / blumgi-slime: bubble-phase delegated click on document → adds `.lvl-pressed` to the captured `.lvl-tile` / `.level-tile` for 1700ms
- stacklands: capture-phase pointerdown delegation on document → adds `.card-tapped` to the captured inner `.card-name` for 1700ms
- CSS flash: scale 1.05-1.15 + brand-color tint + 0.35s ease animation

Verified live: pre/post className deltas confirmed on all 3 games on production CDN. Real-user dead_click rate should drop to near-zero in next 7d window (BI signal confirmation requires a separate observation window).

## P0 Pages workflow unblock (R877c + R878)

### Symptoms
4 consecutive Oct 9 deploy attempts failed (gh runs 37870379941, 37870496998, 37870822727, 37871157065) with opaque "##[error]Process completed with exit code 1." at the actions/upload-pages-artifact@v3 step. tar archive process exited 1 partway through (logged files like `flappy-wings/images/star_*.{png,webp}` and `hide-and-paint/BENCHMARK.md` were the last to print before the error, but the actual culprit was not in the action's error output).

### Root cause
actions/upload-pages-artifact@v3's internal tar invocation uses `--dereference --hard-dereference` to follow symlinks when creating the artifact. If a symlink target is missing (broken), tar exits 1 mid-archive without printing the file name in the action's error log (only shows the opaque "Process completed with exit code 1."). This is a known issue: actions/upload-pages-artifact#58.

### The 2 broken symlinks
```
120000 00b92196b7 0  scripts/daily_growth_latest.md -> daily_growth_2026-07-12.md
   (target file removed; symlink now broken — git show resolves to the symlink string only)
120000 cfee8dae86 0  scripts/daily_seo_latest.md    -> /home/junze/gamezipper.com/scripts/daily_seo_2026-10-09.md
   (absolute path; only exists on local dev machine, missing on CI runner)
```

Both were dev convenience symlinks accidentally committed. The "target" is regenerated daily (`daily_growth_YYYY-MM-DD.md` / `daily_seo_YYYY-MM-DD.md`) and the "latest" symlink was meant to point to the most recent. On CI the absolute path can't resolve.

### Fix (R878)
- `git rm scripts/daily_growth_latest.md scripts/daily_seo_latest.md`
- Both symlinks removed; the underlying data files (`daily_growth_2026-07-12.md`, `daily_seo_2026-10-09.md`, etc.) are still in `scripts/` as regular files
- No data lost
