# R967 (2026-10-20) — SEO health check could not see a broken sitemap

## Finding (P1, SEO monitoring)

`scripts/seo_health_check.py` (run daily by `Daily SEO Health + IndexNow`, 08:30)
validated **HTTP status codes only**. `check_url()` keeps just a 200-character
`content_preview`, and the sitemap branch asserted `status == 200`. Nothing ever
parsed `<loc>` / `<lastmod>`.

So a sitemap that serves **200 with an empty, 0-lastmod, truncated, or
duplicate-laden URL set reports "✅ All checks passed!"** — precisely the
failure that cost 12 days of stale signal in R9357 (COMPLETED.md: sitemap stuck
2026-09-24 behind 437 commits, IndexNow re-pushing the same 819 stale URLs daily
because incremental submit is lastmod-gated).

This is a regression, not a never-existed feature: the report schema in git
history (`git show HEAD:scripts/seo_health_report_2026-10-18.json`,
`script_version: v5.12`) carried `unique_locs` / `with_lastmod` /
`coverage_pct`. The 2026-10-19 05:56 run replaced the rich schema with the
`site_checks`-only schema and those fields stopped being produced at all.

## Negative tests (all three passed silently BEFORE the fix)

Reproduce: start `python3 tests/seo/r967_fake_sitemap_server.py <mode> <port>`,
then `python3 tests/seo/r967_sitemap_neg_test.py <port> gamezipper.com <mode>`.

| mode | sitemap served | pre-fix | post-fix |
|------|----------------|---------|----------|
| `nolastmod`  | 300 URLs, 0 lastmod | rc=0 "All checks passed!" | rc=1 CRITICAL (0.0% coverage) |
| `truncated`  | 5 URLs              | rc=0 "All checks passed!" | rc=1 CRITICAL (below floor 700) |
| `dupes`      | 300 URLs, 1 dupe   | rc=0 "All checks passed!" | rc=1 WARN (duplicate `<loc>`) |

## Fix

- `analyze_sitemap()` parses `<loc>` / `<lastmod>` per `<url>` block and emits
  `unique_locs`, `total_locs`, `with_lastmod`, `coverage_pct`, `duplicate_locs`,
  `newest_lastmod`. Never raises (malformed XML lands in `parse_error`).
- `check_sitemap_content()` gates on `SITEMAP_MIN_URLS` (700 main / 4000 tools,
  set well below the real 819 / 4894 so only a broken generator trips them) and
  requires 100% lastmod coverage.
- `fetch_body()` does the second full-body fetch with retries. **Returns `None`
  on transport failure, not `""`** — otherwise a CDN/TLS blip scores as a
  "0 URLs" CRITICAL and pages us about a healthy sitemap. The `None` path keeps
  the cron wrapper's existing transport-only softening working (verified: rc=0).

## Verification against production (2026-10-20)

```
[OK] gamezipper.com/sitemap.xml       → 200 (819 URLs, 100.0% lastmod, newest 2026-10-17)
[OK] tools.gamezipper.com/sitemap.xml → 200 (4894 URLs, 100.0% lastmod, newest 2026-09-09)
✅ All checks passed!   rc=0
```
No false positives. `daily_seo_health_cron.sh` run end-to-end: exit 0, correctly
silent. Report JSON now carries the `unique_locs`/`coverage_pct` fields again.

## Not defects (do not re-flag)

- **121 game dirs missing from sitemap.xml** — these are canonical-redirect
  stubs (`<title>Anagram is now Text Twist</title>`), correctly excluded.
- **lastmod date clustering** (462 URLs at 2026-07-29, 321 at 2026-10-01) —
  most-recent-commit-date design (R468), documented in COMPLETED.md R9357.
- **tools newest lastmod 2026-09-09** — above the 4000 floor, 100% coverage; the
  long tail is intentional first-commit dating, not a stale generator.
