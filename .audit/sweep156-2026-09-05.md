## Fix Shipped — kakuro P0 (Pitfall #34 — canvas 0×0 on level entry)

### Symptom
Open /kakuro/, click PLAY, click 7x7, click L1.
- game-screen becomes `.active` (display:flex)
- Timer starts counting (00:00 → 00:14)
- Number pad 1-9, Undo, Notes, Hint, Erase buttons all visible
- **game-canvas attribute size stays 0×0 indefinitely**
- Manual `window.dispatchEvent('resize')` → canvas jumps to 165×165 with 27225 RGB pixels (grid renders correctly)

### Root Cause
`startGame()` calls `resizeCanvas()` BEFORE `switchScreen('game')`. At that moment, `#game-grid-container` is inside `.screen` (no `.active` class), so it has `display:none` and `container.clientWidth = 0`. `resizeCanvas()` then sets `canvas.game.width = 0` and `canvas.game.height = 0`. Even after `switchScreen('game')` flips `.active`, the canvas attribute doesn't reset — only `window.resize` event triggers `resizeCanvas` again (which the user won't naturally trigger).

### Fix (commits f6c097d + 5cc68d7)
Move `resizeCanvas()` to AFTER `switchScreen('game')` + defer via double-rAF + setTimeout fallback that retries until container has real dimensions.

```js
function doResize(){
  var c2 = document.getElementById('game-grid-container');
  if (c2 && c2.clientWidth > 0) { resizeCanvas(); return; }
  setTimeout(doResize, 32);
}
requestAnimationFrame(function(){ requestAnimationFrame(doResize); });
setTimeout(doResize, 100);
```

### Verification
- **Before fix (pre-deploy)**: canvas stays 0×0 after wait 5s, wait 10s, wait 30s.
- **After fix v2 (deployed)**: canvas 165×165 rgb=27225 desktop, 340×340 rgb=115600 mobile, 1s after L1 click.
